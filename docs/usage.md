# 설치·사용 안내

## 준비

Windows와 Python 3.11을 사용합니다. 프로젝트 폴더의 명령 프롬프트에서 다음 명령을 순서대로 실행합니다.

```bat
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

설치 목록은 개발 환경에서 확인한 직접 사용 라이브러리와 주요 모델 실행 라이브러리의 버전을 고정했습니다. 모든 간접 의존성을 잠근 lock 파일은 아닙니다. 다른 PC의 신규 설치 성공을 보장하는 검증으로 해석하지 마세요.

## 실행과 종료

- `start_app.vbs`를 더블클릭하면 검은 창 없이 브라우저가 열립니다.
- 대안: `.venv\Scripts\pythonw.exe launcher.pyw`
- 화면이 자동으로 열리지 않으면 `http://127.0.0.1:18766`을 엽니다.
- 같은 실행 파일을 다시 열면 기존 실행 작업을 재사용합니다. 브라우저 탭은 새로 열릴 수 있습니다.
- 화면 아래 **프로그램 종료**를 누르면 실행 작업도 종료됩니다. 탭을 닫는 것만으로는 종료되지 않습니다.
- 바탕화면 바로가기는 `.venv\Scripts\pythonw.exe`를 대상으로, `launcher.pyw`의 전체 경로를 인수로 지정합니다. 시작 위치는 프로젝트 폴더이며 아이콘은 `assets/blog-check.ico`입니다. 개인 컴퓨터의 바로가기 파일 자체는 저장소에 포함하지 않습니다.

## 제목 검사

1. 작성하려는 제목을 입력합니다.
2. 특정 단어가 들어간 글을 반드시 확인하려면 ‘우선 찾을 단어’에 입력합니다.
3. ‘제목 검사하기’를 누릅니다.
4. 후보의 제목과 본문을 확인합니다.

완전 일치와 표기 차이 후보, 지정 단어 후보, 그 외 의미·글자 유사 후보 순으로 정렬합니다. 지정 단어는 의미 점수가 낮아도 결과에 포함합니다. 글자 유사도는 70% 이상, 의미 점수는 사용자가 선택한 기준 이상일 때 후보로 포함합니다.

## 본문 검사

1. 본문 검사 메뉴를 선택합니다.
2. 초안을 붙여 넣거나 ‘기존 글 일부로 테스트하기’를 누릅니다.
3. ‘본문 검사하기’를 누릅니다.
4. 입력 구간과 비슷한 기존 문단을 나란히 검토합니다.

본문 입력은 30,000자까지입니다. 첫 검사는 모델 로딩과 기존 글 임베딩 생성으로 시간이 걸립니다. 준비 결과는 `data/body_cache/`에 저장합니다. 본문을 검사하는 것만으로 새 게시글이 등록되지는 않습니다.

## 실제 네이버 백업 가져오기

1. 네이버에서 받은 ZIP을 압축 해제하고 원본 ZIP을 보관합니다.
2. 다음 명령을 실행합니다.

```bat
.venv\Scripts\python.exe import_backup.py
```

3. 여러 게시글 폴더가 들어 있는 상위 폴더 경로를 입력합니다.
4. 출력한 `data/import_날짜시간/` 폴더에서 `report.json`의 실패·중복 목록과 `preview.txt`의 추출 내용을 확인합니다.
5. 프로젝트의 `local_settings.example.json`을 `local_settings.json`으로 복사하고 실제 경로를 적습니다.

```json
{
  "posts_file": "data/import_실제로생성된폴더/posts.json"
}
```

6. 앱을 새로고침하거나 종료 후 다시 실행합니다.

개인 설정이 없으면 샘플 3개를 사용합니다. 설정된 개인 파일을 찾지 못하면 오류를 표시하며 샘플로 조용히 전환하지 않습니다. 백업이 다른 HTML 구조이면 실패할 수 있습니다. 폴더의 글 수만 보고 성공으로 판단하지 말고 추출한 본문도 확인하세요.

## 새 글 등록과 수정

네이버 게시 후 **글 등록·수정**에서 주소를 입력합니다. 새 주소라면 제목과 본문을 직접 넣습니다. 기존 글 번호가 있으면 저장된 내용을 채워 줍니다. 수정할 때는 확인 항목에 체크하고 저장합니다. 프로그램이 네이버에 게시하거나 네이버의 원문을 수정하지는 않습니다.

- 개인 모드 DB: `data/registered_posts.sqlite3`
- 샘플 모드 DB: `data/sample_registered_posts.sqlite3`
- 저장한 내용은 이후 제목·본문 검사에 포함됩니다.
- 같은 글 번호를 다시 저장하면 새 글 수를 늘리지 않고 갱신합니다.
- 수정 전 내용은 같은 DB의 이력 테이블에 보관합니다. 현재 화면에 이력 복원 기능은 없습니다.

## 데이터 보관

실행 중인 프로그램을 종료한 뒤 `data/`와 `local_settings.json`을 별도 보관하면 개인 글과 등록·수정 내용을 보존할 수 있습니다. 이 파일들은 GitHub 공개 대상이 아닙니다. `data/body_cache/`는 다시 생성할 수 있는 비교 캐시이며 `data/runtime/`은 실행 기록과 임시 제어 정보입니다.

## 문제가 생겼다면

| 증상 | 확인할 내용 |
|---|---|
| `.venv` 또는 Python을 찾지 못함 | `app.py`가 있는 폴더에서 설치 명령을 실행했는지 확인 |
| 아이콘 클릭 후 준비되지 않음 | `data/runtime/server.log` 확인; 첫 설치와 모델 다운로드 시간을 고려 |
| 실행 주소를 사용 중이라는 오류 | 다른 복사본이 켜져 있는지 확인; 다른 프로세스를 무작정 종료하지 않기 |
| 브라우저에서 연결할 수 없음 | 검사 프로그램이 종료됐을 수 있으므로 실행 파일 다시 열기 |
| 첫 본문 검사가 느림 | 진행 숫자 확인; 전체 글 임베딩을 처음 준비하는 단계일 수 있음 |
| 관련 글이 안 나옴 | 핵심 단어 지정 또는 임시 기준 조정; 누락 가능성을 전제로 검토 |
| 개인 글 대신 샘플 3개 표시 | `local_settings.json` 존재 여부와 `posts_file` 경로 확인 |
| 영어 번역 안내가 뜸 | 브라우저의 번역 안내이며 앱 오류가 아님 |

오류 내용을 자세히 보고 싶을 때만 `start.bat`를 사용합니다. 이 방식은 CMD 창을 열며 관리형 실행과 별도 포트에서 실행될 수 있습니다. 혼동을 피하려면 한 방식만 사용하고, 오류 확인 후 CMD에서 Ctrl+C로 종료하세요.
