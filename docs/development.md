# 개발 과정과 문제 해결

## 1. 샘플 제목으로 기본 비교 만들기

Python 3.11.9 환경에서 가상환경을 만들고, 샘플 제목에 `SequenceMatcher`를 적용했습니다. 완전 일치와 공백·문장부호 차이, 글자 유사 후보를 나눴습니다. 이후 제목 데이터를 코드에서 `titles.txt`로 분리해 입력을 바꾸기 쉽게 했습니다. 이 초기 연습 파일들은 현재 공개 구성에서 제외했습니다.

## 2. 글자가 달라도 비슷한 내용을 찾기

공개 Sentence Transformers 다국어 모델을 사용해 제목의 의미를 비교했습니다. 문장을 벡터로 변환하고 코사인 유사도를 계산했습니다. 별도 모델 학습이나 파인튜닝은 수행하지 않았습니다.

## 3. 실제 사용 화면과 백업 연결

명령어 입력 방식에서 Streamlit의 제목 입력칸·검사 버튼·결과 목록으로 전환했습니다. 네이버 백업의 게시글별 HTML에서 제목과 본문 영역을 확인하고 가져오기 기능을 만들었습니다. 실제 백업 처리 결과는 271개 저장, 실패 0개였습니다. 이 데이터는 로컬에서만 사용하며 공개 패키지에는 넣지 않았습니다.

## 4. 의미 검색이 놓친 관련 글

‘주민등록등본 온라인 발급 방법’을 검색했을 때, 원하는 등본 글의 점수는 0.568이었고 다른 증명서 글은 0.737이었습니다. 기준 0.70에서는 원하는 글이 빠졌습니다. 기준을 0.50으로 낮추자 후보는 늘었지만 우선순위 문제가 남았습니다.

데이터 누락 여부와 실제 점수를 확인한 뒤 ‘우선 찾을 단어’ 기능을 추가했습니다. 사용자가 지정한 단어가 제목에 있으면 의미 점수와 무관하게 먼저 보여 줍니다. 이는 검색 규칙의 보완이며 모델 정확도 개선 실험이 아닙니다. 핵심 단어를 사용자가 직접 지정해야 하는 한계도 남아 있습니다.

## 5. 본문을 짧게 나누어 비교

긴 본문을 모델에 한 번에 넣으면 입력 길이 제한으로 뒤쪽이 잘릴 수 있습니다. 문단을 토큰 기준의 짧은 구간으로 나누고 일부를 겹치게 했습니다. 비교 결과는 입력 구간과 기존 문단을 나란히 보여주도록 만들었습니다.

복사한 두 구간은 원문을 1.000으로, 표현을 바꾼 한 구간은 0.766으로 찾았습니다. 한편 가족관계증명서 글의 비슷한 도입부도 후보로 나왔습니다. 따라서 결과를 ‘중복 확정’이 아닌 ‘검토할 후보’로 표시했습니다.

## 6. 지속적으로 사용할 수 있는 글 관리

백업은 과거 글만 담기 때문에 새 글이 검사 대상에 포함되지 않는 문제가 있습니다. 게시글 주소·제목·본문을 저장하고 같은 글 번호는 갱신하도록 SQLite를 도입했습니다. 원본 JSON을 덮어쓰지 않고 저장된 수정 내용을 합쳐 사용하며, 수정 전 내용도 기록합니다.

## 7. 실행 과정과 화면 정리

처음에는 CMD에서 실행했지만, 일반 프로그램처럼 쓰고 싶다는 요구에 맞춰 `pythonw` 실행과 로컬 실행 관리 기능을 추가했습니다. 실행 준비 상태 확인, 이미 실행 중인 작업 재사용, 화면의 종료 버튼을 연결했습니다. Windows의 포트 재사용 동작 때문에 중복 실행 테스트가 실패한 사례를 수정하고 재검사했습니다.

디자인은 밝은 배경과 남색·청록색으로 통일하고 문서·돋보기·체크 모양의 전용 아이콘을 만들었습니다. 별도 데스크톱 GUI나 독립 EXE로 변환한 것은 아닙니다.

## 8. 공개 패키지 분리

개인 데이터·설정·캐시·가상환경을 제외하고 샘플 글로 실행되는 패키지를 만들었습니다. 코드에 있던 개인 데이터 폴더 선택을 별도 로컬 설정으로 분리했습니다. 샘플 등록 DB와 개인 등록 DB도 분리했습니다.
